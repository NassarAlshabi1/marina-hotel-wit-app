## 2. المنهج

### 2.1 بناء D1 محلياً (مسار التثبيت الجديد)

```bash
npx wrangler d1 execute marina-hotel-db --local --persist-to /tmp/d1fresh --file=./schema.sql
```

النتيجة: **34 جدول تطبيق + `_cf_METADATA` = 35**، 808 عموداً، 107 فهرساً. تطبيق `schema.sql` نظيف بلا أخطاء، وأعمدة 0019 (`hotel_day_key`, `applied_date`) موجودة، والفهرس الفريد `ux_booking_nights_booking_day_live` موجود.

### 2.2 مقارنة «الترقية» (الهجرات) بـ«التثبيت الجديد» (`schema.sql`)

| الفحص | النتيجة |
|---|---|
| أعمدة تضيفها هجرة ولا توجد في `schema.sql` | **صفر** |
| جداول تنشئها هجرة ولا توجد في `schema.sql` | 3، وكلها **جداول إعادة بناء مؤقتة** تُحذف/تُعاد تسميتها داخل الهجرة نفسها: `devices_sync_rebuild` (0004)، `price_adjustments_parity_rebuild` (0005)، `booking_nights_v2` (0018) — لا انحراف |
| فهارس تنشئها هجرة ولا توجد في `schema.sql` | **1** → `idx_salary_withdrawals_employee_uuid` (0006) ← **F1، أُصلح** |

الحارس الجديد `npm run check:schema` (‏`scripts/check-schema-drift.mjs`) يفشل بـexit 1 عند أي انحراف مستقبلي، ويتجاهل جداول إعادة البناء تلقائياً. تحقّقنا من فعاليته بالطريقتين:

```
# بعد إزالة الفهرس من schema.sql
✗ انحراف: migrations/0006...: الفهرس idx_salary_withdrawals_employee_uuid غير موجود في schema.sql
exit=1
# بعد الإصلاح
✓ لا انحراف: 18 هجرة، 34 جدول، 107 فهرس
exit=0
```

### 2.5 التحقق الوظيفي لملف الفحص

`audit-d1.sql` لا يكفي أن يُنفَّذ بلا خطأ — يجب أن **يكشف** الخلل فعلاً. بُنيت قاعدة تجريبية ملوّثة بـ8 عيوب معروفة:

| العيب المزروع | الفحص الذي أطلقه |

| ليلتان بلا `booking_uuid_cache` لنفس (الحجز، اليوم) | `live_nights_without_booking_uuid = 2` |
| ليلة بـuuid حجز غير موجود | `orphan_nights_missing_booking = 1` |
| ليلة مربوطة بحجز آخر غير صاحب uuidها | `nights_linked_to_wrong_booking = 1` |
| ليلة بمعرّف حجز صفري | `nights_with_zero_booking_link = 1` |
| مدفوعة بلا هوية حجز | `payments_without_booking_uuid = 1` |
| سحوبة بلا `employee_uuid` | `withdrawals_without_employee_uuid = 1` |

## 3. ما يجب تنفيذه على D1 الحقيقي

```bash
cd worker

# 0) نسخة احتياطية إلزامية قبل أي شيء
npx wrangler d1 export marina-hotel-db --remote --output backup-d1-$(date +%F).sql

# 1) فحص الحالة (قراءة فقط) — 29 صفاً
npm run audit:d1:remote

# 2) نشر الشيفرة الحالية (تشمل تحويل 0019 وأعمدة التسويات)
npm run db:migrate:bpa-columns:remote    # مرة واحدة فقط — SQLite بلا ADD COLUMN IF NOT EXISTS
npm run deploy

# 3) إعادة الفحص بعد الترقية
npm run audit:d1:remote
```

**تفسير النتائج:**

| النتيجة | المعنى | الإجراء |
|---|---|---|
| `price_adjustments_day_aliases_null > 0` | الترحيل `0019` لم يُنفَّذ بعد على القاعدة الحقيقية | نفّذ `db:migrate:bpa-columns:remote` |
| `duplicate_live_nights > 0` | تكرار حقيقي حيّ على الخادم (يستحيل مع الفهرس الحالي ⇒ بيانات قديمة أو جدول أُنشئ قبل 0018) | أعد بناء الليالي من التطبيق ثم `npm run audit:d1:remote` |
| `orphan_nights_missing_booking` أو `nights_linked_to_wrong_booking` > 0 | يتامى/روابط خاطئة | لا حذف يدوي؛ شغّل «إصلاح الإقلاع» في التطبيق ليطويها ويُخرج شواهد قبور، ثم أعد الفحص |
| `withdrawals_without_employee_uuid > 0` | سحوبات بلا أب (كانت 30) | لا شيء بعد ترقية العملاء؛ تُحجز تدريجياً وتُعزل |
| `idempotency_log_rows > 5000` | تنظيف cron لا يعمل | راجع `maintenance.ts` وسجل `cron` في لوحة Cloudflare |
| `bookings_with_more_than_60_nights > 0` | اشتباه تضخّم ليالي حجز واحد | راجع الحجز المحدد في التطبيق |
