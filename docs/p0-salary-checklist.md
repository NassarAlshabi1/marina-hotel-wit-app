# مطابقة قائمة P0 مع فرع Android الحالي

القائمة المرسلة تشير إلى 8 بنود، لكن النص المتاح يحوي P0.1–P0.6 فقط، وينتهي عند «Drive». مصدر Flutter (`mobile/lib`) غير موجود في هذا checkout، ولا يظهر commit `1c83e916` في قاعدة Git المحلية. لذلك هذه مطابقة للمكافئ الموجود في Kotlin وليست ادعاء تعديل دوال Dart أو استعادة ذلك commit حرفيًا.

| البند | الحالة في هذا الفرع |
|---|---|
| P0.1 حفظ السجلات اليتيمة بدل الحذف | لا توجد `_performPostSyncIntegrityCheck` أو عملية DELETE تلقائية لسجلات الرواتب اليتيمة. الاستيعاب يؤجلها إلى `pending_sync_links` ويحفظها. أضيف تحذير بعدد السجلات المؤجلة دون تسجيل بيانات مالية أو شخصية. لا يُمسح أي تاريخ. |
| P0.2 إزالة مطابقة remote id = local id | موجود مسبقًا: `resolveEmployee` و`resolveSalaryCycle` يستخدمان UUID، أو ظل `server_id` الفريد عند غياب UUID، وليس المفتاح المحلي. أضيف اختبار تصادم الرقم المحلي مع موظف غير معني. |
| P0.3 حارس الموظف والمحلية | أُضيف تحقق ملكية UUID للمصروف والسحب وللموظف المختار قبل التعديل/الحذف. لا يكفي الرقم المحلي أو `exp_N`، حتى مع تطابق الأرقام. حفظ السحب المباشر يرفض تعارض UUID مع الموظف المختار. إعادة تعيين الموظف الصحيحة تمرر UUID الموظف السابق من داخل معاملة المصروف للتحقق من السحب القديم، ثم تغيّر العلاقة. الشاشات لا تستدعي إنشاء/حذف التمثيل منفصلًا؛ تملكه `ExpensesRepositoryImpl`. |
| P0.4 relatedId و«سلفة» | موجود مسبقًا: تصنيف `EmployeeExpenseTypes` يتضمن «سلفة»، و`SyncIngestorRegistry` لا يستعمل `related_id` الخام لربط مصروف موظف وارد. UUID المفقود لا يُستبدل بتخمين محلي، والوالد غير الواصل يُؤجل. لا يوجد ملف `expenses_adapter` من Dart هنا. |
| P0.5 السحب اليتيم يبقى في الطابور | الخادم يعيد فشلًا ولا يسجل idempotency ناجحًا عند غياب الموظف. أضيف اختبار سبع محاولات ثم وصول الأب ونجاح المفتاح نفسه مرة واحدة. Android يستثني `salary_withdrawals` من تحويل الأخطاء العابرة إلى dead-letter بسبب عدد المحاولات؛ تبقى غير مسلّمة وتُعاد في دورات المزامنة. الرفض الصريح الدائم `validation_error/conflict` ما زال يحتاج مراجعة، ولا يُعدّ تسليمًا ناجحًا. لا تُعاد تلقائيًا طلبات دُفنت سابقًا قبل هذا التعديل. |
| P0.6 إضافة الجدولين إلى Drive | **غير مكتمل / يحتاج المصدر المقصود.** لا يوجد موصل Google Drive في الفرع. النسخ المحلي يتضمن بالفعل `salary_withdrawals` و`salary_carry_over_logs`، وأضيف اختبار لقائمة جداول النسخ. ذلك ليس اختبار رفع/استعادة Drive ولا تنفيذًا لموصل جديد. |
| البندان الآخران | لم يصلا؛ يلزم النص الكامل. |

## حدود الحماية

- الربط المستقر بـ UUID صالح عبر الأجهزة. لا نفرض ملكية الجهاز على حركة مزامنة سليمة؛ الحظر يتعلق بالتخمين من أرقام جهاز آخر.
- السحب الذي يفتقد UUID موظف موثوقًا لا يُعدّل أو يُحذف عبر المصروف بالتخمين. تبقى البيانات للمراجعة.
- معاملات Room تحمي المصروف والسحب وOutbox من أي تعديل جزئي عند رفض الحارس.
- لا تغييرات على مخطط البيانات أو ترحيلات إنتاج، ولا إعادة لميزة القيود العكسية وإقفال الفترات التي تم التراجع عنها.

## أدلة الاختبار

- `SyncIngestorRegistryTest`: حارس الموظف المختلف، rollback للمصروف وOutbox، رفض الرقم المحلي المستورد، إبقاء محاولات السحب قابلة للإعادة، تصادم أرقام الموظفين، وقائمة جداول النسخ المحلي. اختبار إعادة تعيين الموظف السابق باقٍ للتحقق من عدم تعطيل المسار المشروع.
- `worker/test/sync.integrity.test.ts`: 11 حالة، تتضمن محاولة السحب اليتيم بالمفتاح نفسه قبل وصول الموظف وبعده.
- نتائج Android تُتحقق عبر GitHub Actions؛ وجود الاختبار في الكود وحده لا يعني نجاح تشغيله.
