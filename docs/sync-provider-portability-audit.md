# تدقيق نقل مزوّد المزامنة — الحالة الحالية وخطة الخطوة التالية

**التاريخ:** 2026-10-06
**الفرع:** `arena/4d28efc6-marina-hotel-wit-app`
**النطاق الذي فُحص:** Android/Kotlin + Cloudflare Worker/D1 في هذا الفرع.
**مرجع المتطلبات:** `مسودة.md`، وخصوصًا الملحق التنفيذي الأحدث وحدود عدم تخمين الروابط وعدم نشر Worker أو تعديل بيانات الإنتاج.

## الخلاصة التنفيذية

**الروابط المالية بالـUUID، وOutbox، والعلاقات المؤجلة والحجر، وتصنيف المصروفات تشكل أساسًا جيدًا للمزامنة الحالية بين العملاء المتوافقة مع عقد Worker. لكنها لا تجعل تغيير عنوان Worker إلى مزوّد مزامنة آخر عملية نقل آمنة.**

ميزة العنوان المخصص الموجودة هي مسار بديل لنطاق **Worker نفسه**؛ ليست اختيار مزوّد جديد ولا نسخ بيانات. لذلك لا تستخدم «حفظ النطاق المخصص» أو «السحب الكامل» كطريقة انتقال من Cloudflare إلى قاعدة/خدمة أخرى. لم أجد في هذا الفرع موصلًا ثانيًا أو إجراء cutover/ترحيل بيانات بين مزوّدين.

هذا تدقيق للشجرة المحلية فقط: **لم يُتصل ببيانات الفندق الإنتاجية، ولم تُشغّل ترحيلات أو كتابة خارجية أو نشر أو تدوير epoch.** لم تُغيّر معادلات مالية أو علاقات تاريخية.

## نقطة مهمة عن مصدر التطبيق

الشجرة الحالية تتضمن `mobile/android/` و`worker/`، ولا تتضمن تطبيق Flutter/Dart أو Drift. ويذكر `worker/README.md` صراحة أن عميل هذا المستودع هو Android/Kotlin. كما ينص ملحق `مسودة.md` على أن نقل الإصلاحات إلى Flutter لم يُنفذ في ذلك المصدر المرجعي.

لهذا التقرير أقيم Android/Worker الموجودين هنا؛ **لا أصفه بأنه تدقيق Flutter، ولا أنقل أرقام Room أو Worker تلقائيًا إلى Drift.** إذا كان التنفيذ المقصود على Flutter، فيلزم توفير checkout الذي يحتوي مصدر Flutter في جلسة مناسبة؛ جلسة Arena الحالية مثبتة على فرع Android أعلاه.

## ما وجدته في التنفيذ

| المجال | الموجود الآن | الأثر عند الانتقال إلى مزوّد مختلف |
|---|---|---|
| عنوان الخادم | `WorkerEndpoints` ما زال يبقي النطاق المخصص و`workers.dev` ضمن failover؛ المقصود alias لنفس Worker. العميل الجديد يثبت D1 الحالي، ويضع `X-Sync-Source-Id` على عمليات pull/push؛ Worker الجديد يرفض المرشح الآخر إذا كانت هويته مختلفة. | لا يزال `/api/ping` وحده لا يثبت المصدر. الحماية تتطلب تطبيق 0016 ونشر Worker الجديد قبل Android؛ Worker قديم أو نطاق لم يُحدّث لا يفرض الترويسة خادميًا. هذه آلية رفض وليست نقلًا بين المصدرين. |
| فحص النطاق | `CloudflareSyncSettingsViewModel.probeCustomEndpoint()` ينتهي إلى `CloudflareSyncService.ping()`؛ Retrofit يستخدم interceptor نفسه. نتيجة `ping` هي نجاح `/api/ping` فقط، ولا تحدد أي مضيف أجاب أو توافق بروتوكوله. | نجاح الفحص لا يثبت هوية قاعدة البيانات، ولا يكفي لإعلان جاهزية خدمة مزامنة أخرى. |
| عقد النقل | التنفيذ ما زال معتمدًا على `CloudflareWorkerApi` و`CloudflareSyncService`; أضيف handshake للمزوّد/المصدر/إصدار البروتوكول وحارس للترويسة. | التفاوض الحالي يثبت الإصدار والهوية فقط؛ لا يوجد adapter ثانٍ أو تفاوض قدرات شامل أو إجراء نقل. `SyncRepository` لا يوفّر بمفرده انتقالًا بين مخازن. |
| حالة السحب | `SyncPreferences` لا يزال يحفظ cursor/epoch عامين، لكن `SyncManager` يتحقق الآن من source id المعتمد قبل كل دورة؛ mismatch يمنع push/pull، وfull pull يفحص الهوية قبل تصفير cursor. | لا يحدث فصل كامل لحالة cursor حسب عدة مصادر ولا auto-rebind. تبديل مصدر مستقبلي يحتاج إجراء نقل واعتماد يحفظ الحالة المناسبة؛ لا يكفي epoch وحده. |
| الرفع | `OutboxRepository.processPending()` يرسل العمليات غير المسلّمة فقط. عند نجاح التسليم يمكن تنظيف صفوف Outbox. | السجلات التي سُلّمت سابقًا لا تصبح عمليات Outbox جديدة عند تغيير العنوان؛ لذلك رفع المتبقي فقط لا ينشئ نسخة كاملة في الخادم الجديد. |
| السحب الكامل | `SyncManager.performFullPull()` يصفّر cursor ويطلب صفحات pull فقط؛ لا يصدّر كل الصفوف المحلية ولا ينسخها إلى المصدر الجديد. | «سحب كامل» يعيد قراءة ما لدى المصدر الحالي، وليس ترحيلًا من المصدر القديم. |
| النسخ والاستعادة | النسخة المحلية تشمل جداول الأعمال وتستبعد Outbox والحالة الداخلية؛ استعادة JSON تعيد ضبط المؤشرات. النسخ الجديدة تحفظ `sync_source_id` في metadata وتستعيده إن وُجد. | النسخة ما زالت ليست بروتوكول نقل بين خادمين: لا تدير القطع أو المقارنة ولا تنسخ Outbox؛ النسخ القديمة بلا الهوية لا تُحوّل إلى نسخة مصدر موثوقة بأثر رجعي. |
| رفع D1 المباشر | `CloudflareD1BackupService.uploadData()` موقوف عمدًا برسالة تمنع الكتابة المباشرة التي قد تعيد ترقيم المفاتيح أو تتجاوز عقد المزامنة. | لا يوجد مسار بديل آمن لنسخ جميع البيانات من هذه الشاشة؛ وهذا الإيقاف يجب الحفاظ عليه، لا تجاوزه بـ`INSERT OR REPLACE`. |
| هوية الخادم | قبل هذا التغيير لم يكن `/api/health/d1` يعلن هوية مصدر أو إصدار بروتوكول. أضيف الآن `sync_provider`, و`sync_source_id` ثابتاً لكل قاعدة، و`sync_protocol_version`; كما يرفض Worker push/pull المربوط بهوية مختلفة. | Android يثبت هوية المصدر بعد أول فحص صالح ويرفض الاختلاف لاحقاً قبل عمليات المزامنة. هذا حاجز من التبديل الصامت، لا آلية نسخ أو ترحيل بيانات. |

### نتيجة عملية مهمة

السيناريو التالي غير مضمون: تغيير العنوان إلى خدمة فارغة ثم اختيار «رفع» أو «سحب كامل». الرفع يضم المتبقي في Outbox فقط، والسحب الكامل يقرأ الهدف فقط. البيانات التي سبق تسليمها إلى Cloudflare قد لا تكون في Outbox، وستبقى في الجهاز/المصدر القديم بدل أن تُنسخ تلقائيًا إلى المصدر الجديد.

## العقد المحايد المنفذ بعد اختيار المستخدم

- أضيفت migration محلية `worker/migrations/0016_sync_source_identity.sql`: تضيف `source_id` ثابتًا للمصدر الحالي (القيمة المعتمدة تطابق D1 ID بعد حذف الشرطات) دون لمس السجلات أو epoch أو المؤشرات؛ وهي idempotent. Android يثبت هذه القيمة المعتمدة؛ أما `schema.sql` لقاعدة مستقلة جديدة فيولّد لها هوية مستقلة.
- يعرض `/api/health/d1` الحقول `sync_provider=cloudflare-d1`, و`sync_source_id`, و`sync_protocol_version=1`. غياب الهوية لا يؤدي إلى توليدها تلقائيًا من مسار الصحة.
- يثبت Android أول هوية متوافقة في `SyncPreferences`، ويفحصها قبل push/pull والسحب الكامل. اختلاف المزوّد أو الإصدار أو هوية المصدر يوقف الدورة قبل استنزاف Outbox أو إعادة ضبط cursor، مع رسالة خطأ، ولا يعيد الربط تلقائيًا.
- يرسل Android `X-Sync-Source-Id` مع الطلبات المحمية؛ ويفحص Worker الترويسة قبل تشغيل push/pull. هذا يغلق نافذة اختلاف المصدر بين probe والعملية على Worker الذي يطبق العقد.
- تتضمن ميتاداتا النسخ JSON/sidecar الجديدة `sync_source_id` عند توفره؛ استعادة JSON تربط الجهاز بهوية النسخة، مع استمرار عدم استيراد cursor أو Outbox من جهاز آخر. النسخ القديمة بلا هذا الحقل لا نستنتج لها هوية بأثر رجعي.
- Android الحالي يقبل `cloudflare-d1` فقط؛ لا يوجد connector لخدمة ثانية ولا بروتوكول نقل/تفعيل مصدر جديد. هوية النسخة معرّف للقاعدة لا للنطاق، والنطاقات البديلة يجب أن تصل إلى D1 نفسه.

**حدود الحماية:** التثبيت الأول في Android لا يقبل أي استجابة عشوائية؛ إنه مقيد بـ`EXPECTED_SYNC_SOURCE_ID` المأخوذ من معرّف D1 الحالي، ثم يثبت الهوية محليًا. لذلك يتوقف Worker على قاعدة مختلفة حتى لو كان البروتوكول نفسه. إذا تغير المصدر المعتمد مستقبلًا، يلزم إصدار/إجراء اعتماد صريح غير موجود الآن. كما أن نسخ `sync_meta` كاملة إلى قاعدة مستقلة ينسخ الهوية معها؛ إنشاء هوية مستقلة بعد استيراد بيانات يحتاج إجراء اعتماد/نقل صريحًا غير منفذ هنا. العقد يرفض التبديل اللاحق، لكنه لا يرحّل البيانات ولا يثبت اكتمال نقل.

**ترتيب الإطلاق الذي وثقته:** تحقق يدويًا من سجل ومخطط D1 والنسخة الاحتياطية؛ طبّق 0016 على القاعدة الصحيحة، ثم انشر Worker، ثم تحقق من هوية كل نطاق قبل إصدار Android. لم أنفذ أي خطوة من هذه الخطوات على D1 الإنتاجي.

## ما هو موجود ويجب الحفاظ عليه

- Room حاليًا **75**، ومخطط Worker يتضمن `expense_kind` مع migration `0015` في هذا المصدر. هذه أرقام لهذا الفرع فقط، وليست أرقامًا لقاعدة Flutter/Drift أو إثباتًا بتطبيق migration على الإنتاج.
- الكيانات المالية تستخدم UUIDs ثابتة، والربط بين المصروف ومرآة السحب يستخدم `expense_uuid`، وروابط الموظف/الدورة تشمل `employee_uuid` و`cycle_uuid`. الأرقام المحلية ليست هوية عابرة للأجهزة؛ يبقى توافق تاريخي محدود لـ`server_id` موثقًا ولا ينبغي توسيعه إلى FK محلي خام.
- الحفظ المالي وOutbox لهما اختبارات معاملات ومفاتيح idempotency؛ الروابط المؤجلة محفوظة في `pending_sync_links`، والأخطاء غير الصالحة في `sync_quarantine` بدل إسقاطها بصمت.
- `expense_kind` يحمي التصنيف من تغيّر الوصف، وتوجد اختبارات للأنواع وواجهات Worker. هذا يحافظ على معنى الحركة لكنه لا ينشئ آلية نقل مزوّد.
- لا يجوز دمج سحوبات مستقلة متساوية في المبلغ/اليوم أو تخمين روابط التاريخ من رقم محلي أو اسم أو تشابه مبلغ.

## التحقق المحلي في هذه الجلسة

- `cd worker && npm ci --no-audit --no-fund` — نجح (`added 99 packages`).
- `cd worker && npm run typecheck` — نجح، ويشمل مصدر الإنتاج والاختبارات.
- اختبارات Worker المركزة للهوية والصحة: **9/9** عبر `health.d1.test.ts`, و`provider.portability.audit.test.ts`, و`sync.source.identity.test.ts`.
- مجموعة Worker كاملة بعد التغييرات: **232/232 اختبارًا نجحوا** في 23 ملفًا.
- كمرجع تاريخي فقط، قبل هذا التغيير كانت هناك محاولتان كاملتان سابقًا بنتيجة 226/227 مع فشل مختلف متقطع، بينما نجح اختبار rate-limit المنفرد. التشغيل الكامل الحالي أخضر؛ لا تنسب نتائج baseline إلى التشغيل الحالي.
- `cd mobile/android && ./gradlew :app:testDebugUnitTest` توقف قبل التجميع برسالة غياب Java (`JAVA_HOME` غير مضبوط ولا يوجد `java`). لذلك لم تُنفّذ اختبارات Kotlin/نسخ Android فعليًا في هذه البيئة.
- فحص JSON لـ`worker/package.json` و`git diff --check` نجحا.
- استُخدم Worker/D1 المحلي فقط للاختبارات؛ لا اتصال ببيانات إنتاج، ولا migration فعلي، ولا نشر Worker، ولا تغيير مالي/تاريخي.

## ما تبقى قبل أي نشر أو نقل فعلي

1. شغّل اختبارات Android/Kotlin على بيئة فيها JDK/Android SDK؛ لم يمكن تشغيلها في هذه البيئة.
2. قبل إصدار Android، افحص مخطط وسجل D1 الإنتاجي يدويًا، وأخذ نسخة واختبار استعادتها؛ بعدها فقط يقرر المشغّل تنفيذ migration 0016 ثم Worker deploy ثم التحقق من كل alias. لم يحدث أي من ذلك هنا.
3. إذا كانت النسخة الاحتياطية قديمة بلا `sync_source_id`، فافحص مصدر بياناتها قبل استعادتها؛ ففحص التطبيق يثبت وجهة Worker الحالية ولا يستطيع استنتاج مصدر ملف قديم.
4. اعتمد مزوّدًا ووفّر مصدره الفعلي قبل تصميم adapter ثانٍ وإجراء نقل: جرد UUID والعلاقات والحقول المالية والحذف وOutbox، استيراد متحقق منه، حواجز القطع/الاستئناف والرجوع، دون dual-write عشوائي أو تخمين روابط أو تعديل معادلات.
5. نفّذ اختبارات قبول على قواعد محلية/staging فقط: جهازان، ومعرفا موظفين محليان مختلفان، ورواتب ومصروفات بروابط UUID، عمليات مستقلة متساوية، طفل قبل الأب، حذف صريح، Outbox عند الانقطاع، إعادة محاولة، cursor/epoch متطابق أو غائب، واستعادة نسخة. معيار النجاح: تطابق UUIDs والعلاقات والحقول المالية ومجاميعها قبل/بعد، بلا فقد أو تكرار أو تخمين تاريخي.
6. اعرض التقرير والـdiff قبل النشر؛ لا تنفيذ ترحيل D1 الإنتاجي أو نشر Worker أو cutover دون موافقة تشغيلية مستقلة.

**القرار الحالي:** نُفّذ حاجز source/protocol على Android الحالي وWorker، واختباراته المحلية الموجهة ناجحة. هذا لا يغيّر بيانات ولا ينقلها، ولا ينفذ موصلًا لمزوّد غير محدد. النقل بين Cloudflare ومزوّد آخر ما زال **غير منفذ وغير مختبر**؛ لا تغيّر العنوان على أجهزة الفندق على أساس أن ذلك ينقل البيانات.
