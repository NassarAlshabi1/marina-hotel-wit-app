# Manus Security Review

يستخدم المستودع Workflow مملوكاً له باسم **Manus Security Review** بدلاً من الاعتماد على تشغيل GitHub Advanced Security الديناميكي الذي يستخدم Copilot. يقسّم السكربت diff الكبير إلى أجزاء مستقلة تحت حد Manus API ثم يجمع findings في تقرير واحد، حتى يمكن مراجعة PRs الكبيرة دون تجاوز حد محتوى الرسالة. يتعامل السكربت مع عدم الاتساق المؤقت بعد إنشاء مهمة Manus؛ فإذا أعاد `task.listMessages` حالة `task not found` في الثواني الأولى، يستخدم إعادة محاولة تدريجية قبل اعتبار الاعتماد أو صلاحية المهمة غير صحيحة. يعمل هذا المسار كمراجعة أمنية مدعومة بـ Manus، بينما تبقى CodeQL وSemgrep وTrivy وGitleaks وفحوصات الاعتماديات هي طبقة الكشف الأساسية القابلة لإعادة الإنتاج. يستخدم Workflow حدث `pull_request_target`، ويشغّل السكربت من نسخة الفرع الموثوقة ويقرأ diff لفرع الطلب فقط؛ ولا ينفذ كوداً قادماً من PR مع وجود السر في البيئة.

## التفعيل

أضف Secret باسم `MANUS_API_KEY` من إعدادات المستودع في:

`Settings → Secrets and variables → Actions → New repository secret`

لا تضع المفتاح في ملفات YAML أو السكربتات أو `.env` أو رسائل Pull Request. عند غياب Secret، يتجاوز Workflow مراجعة Manus مع رسالة واضحة في Summary، ولا يفشل البناء؛ وهذا مقصود حتى لا تصبح المراجعة الذكية نقطة توقف قبل تهيئة الاعتماد.

## نطاق البيانات المرسلة

يرسل السكربت diff موحداً للتغييرات فقط، وليس كامل المستودع. يستبعد مجلدات الوثائق و`node_modules` والملفات المولَّدة (`*.g.dart` و`*.freezed.dart` و`*.mocks.dart`) وملفات الأقفال (`package-lock.json` و`pubspec.lock`)، ويزيل قيم الأنماط الشائعة للمفاتيح والرموز وكلمات المرور قبل الإرسال. يجب مع ذلك اعتبار diff بيانات قد تحتوي على معلومات خاصة، ولذلك ينبغي استخدام مفتاح Manus ضمن حساب أو مساحة العمل المصرح بها للمشروع.

### ميزانية المراجعة للطلبات الكبيرة

كل قطعة تُرسَل كمهمة Manus مستقلة ويُنتَظر اكتمالها، لذلك تُحدَّد المراجعة بعدد قطع (`--max-chunks`، الافتراضي 12) وليس بحجم إجمالي صارم. عند تجاوز الميزانية تُرتَّب الملفات حسب الأولوية الأمنية (ملفات `.github/workflows` ثم `scripts` ثم PHP ثم ملفات المصادقة والشبكة وقاعدة البيانات ثم بقية Dart/JS/YAML، مع مكافأة إضافية عند وجود أنماط حساسة داخل القطعة)، وتُذكَر الملفات غير المراجَعة صراحةً في `excluded_files` وفي قسم «Review scope» في التقرير. لا يفشل الفحص بسبب حجم الطلب؛ فشريحة المراجعة الاستشارية يجب ألا تتحول إلى حاجز وهمي، بينما تبقى الفحوصات الساكنة هي الأساس. يمكن رفع العدد عبر `workflow_dispatch` بمدخل `max_chunks` عند الحاجة إلى تغطية أوسع.

## شكل النتيجة

يطلب Workflow مخرجاً JSON مهيكلاً يتضمن مستوى الخطورة، الثقة، الملف والسطر والدليل والتبرير والمعالجة. لا يفشل Workflow تلقائياً عند نتيجة Manus؛ فالمراجعة الذكية قد تخطئ أو تفوّت مشكلة. إذا ثبتت الحاجة إلى جعل النتائج عالية الخطورة حاجزاً، يمكن ضبط `MANUS_SECURITY_BLOCKING=true` بعد اختبار داخلي ومراجعة بشرية، مع إبقاء الفحوصات الساكنة مستقلة.

## تشخيص الفشل السابق

التشغيل الديناميكي `github-advanced-security` فشل برسالة `Bad credentials` عند محاولة قراءة تعليقات Copilot السابقة. هذا المسار الجديد لا يستخدم Copilot ولا يعتمد على تعليقات Copilot أو اعتماداته. يعتمد فقط على `MANUS_API_KEY` في GitHub Actions، ويظل منفصلاً عن الموصلات المحلية المستخدمة أثناء جلسة Manus.

### فشل PR #636 (run 39314309799)

فشل خطوة «Run Manus security review» خلال أقل من ثانية بالخطأ `Redacted diff exceeds the configured 1.5 MB review limit`. السبب: الطلب غيّر 1490 ملفاً، فأنتج `git diff --unified=80` نصاً بحجم 4.75 MB، وكان السكربت يرمي استثناءً فورياً عند تجاوز 1.5 MB قبل أي اتصال بالـ API. الإصلاح: خفض السياق إلى `--unified=8` واستبعاد الملفات المولَّدة وملفات الأقفال (4.75 MB ← 1.2 MB)، واستبدال الحد الصارم بميزانية قطع مرتَّبة بالأولوية مع الإفصاح عن الملفات غير المراجَعة. الاختبارات الانحدارية في `scripts/tests/test_manus_security_review.py` تُشغَّل عبر `python3 -m unittest discover -s scripts/tests`.

## التشغيل المحلي

```bash
python3 scripts/manus_security_review.py \
  --diff-file manus-review.diff \
  --sha <commit-sha> \
  --max-chunks 12 \
  --json-output manus-security-report.json \
  --markdown-output manus-security-report.md
```

للتشغيل الفعلي يجب توفير `MANUS_API_KEY` في البيئة، ولا ينبغي طباعته أو تمريره ضمن سطر الأوامر. يمكن ضبط الميزانية أيضاً عبر المتغير `MANUS_MAX_CHUNKS`.

## الاختبارات

```bash
python3 -m unittest discover -s scripts/tests -v
```

تغطي الاختبارات تخطيط الميزانية وترتيب الأولوية وتقسيم القطع وإخفاء بيانات الاعتماد ودمج النتائج، بما في ذلك اختبار انحدار لحجم diff الخاص بـ PR #636.
