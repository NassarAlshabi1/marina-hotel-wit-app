# Manus Security Review

يستخدم المستودع Workflow مملوكاً له باسم **Manus Security Review** بدلاً من الاعتماد على تشغيل GitHub Advanced Security الديناميكي الذي يستخدم Copilot. يتعامل السكربت مع عدم الاتساق المؤقت بعد إنشاء مهمة Manus؛ فإذا أعاد `task.listMessages` حالة `task not found` في الثواني الأولى، يستخدم إعادة محاولة تدريجية قبل اعتبار الاعتماد أو صلاحية المهمة غير صحيحة. يعمل هذا المسار كمراجعة أمنية مدعومة بـ Manus، بينما تبقى CodeQL وSemgrep وTrivy وGitleaks وفحوصات الاعتماديات هي طبقة الكشف الأساسية القابلة لإعادة الإنتاج. يستخدم Workflow حدث `pull_request_target`، ويشغّل السكربت من نسخة الفرع الموثوقة ويقرأ diff لفرع الطلب فقط؛ ولا ينفذ كوداً قادماً من PR مع وجود السر في البيئة.

## التفعيل

أضف Secret باسم `MANUS_API_KEY` من إعدادات المستودع في:

`Settings → Secrets and variables → Actions → New repository secret`

لا تضع المفتاح في ملفات YAML أو السكربتات أو `.env` أو رسائل Pull Request. عند غياب Secret، يتجاوز Workflow مراجعة Manus مع رسالة واضحة في Summary، ولا يفشل البناء؛ وهذا مقصود حتى لا تصبح المراجعة الذكية نقطة توقف قبل تهيئة الاعتماد.

## نطاق البيانات المرسلة

يرسل السكربت diff موحداً للتغييرات فقط، وليس كامل المستودع. يستبعد مجلدات الوثائق و`node_modules`، ويزيل قيم الأنماط الشائعة للمفاتيح والرموز وكلمات المرور قبل الإرسال. يوجد حد أقصى قدره 1.5 MB للنص المرسل. يجب مع ذلك اعتبار diff بيانات قد تحتوي على معلومات خاصة، ولذلك ينبغي استخدام مفتاح Manus ضمن حساب أو مساحة العمل المصرح بها للمشروع.

## شكل النتيجة

يطلب Workflow مخرجاً JSON مهيكلاً يتضمن مستوى الخطورة، الثقة، الملف والسطر والدليل والتبرير والمعالجة. لا يفشل Workflow تلقائياً عند نتيجة Manus؛ فالمراجعة الذكية قد تخطئ أو تفوّت مشكلة. إذا ثبتت الحاجة إلى جعل النتائج عالية الخطورة حاجزاً، يمكن ضبط `MANUS_SECURITY_BLOCKING=true` بعد اختبار داخلي ومراجعة بشرية، مع إبقاء الفحوصات الساكنة مستقلة.

## تشخيص الفشل السابق

التشغيل الديناميكي `github-advanced-security` فشل برسالة `Bad credentials` عند محاولة قراءة تعليقات Copilot السابقة. هذا المسار الجديد لا يستخدم Copilot ولا يعتمد على تعليقات Copilot أو اعتماداته. يعتمد فقط على `MANUS_API_KEY` في GitHub Actions، ويظل منفصلاً عن الموصلات المحلية المستخدمة أثناء جلسة Manus.

## التشغيل المحلي

```bash
python3 scripts/manus_security_review.py \
  --diff-file manus-review.diff \
  --sha <commit-sha> \
  --json-output manus-security-report.json \
  --markdown-output manus-security-report.md
```

للتشغيل الفعلي يجب توفير `MANUS_API_KEY` في البيئة، ولا ينبغي طباعته أو تمريره ضمن سطر الأوامر.
