## إصلاحات السلوك ومعالجة الأخطاء

- فصل نقل HTTP الخاص بنسخ Cloudflare D1 في `D1HttpClient` عن SQL والتجميع ومصدر البيانات. لم تتغير عبارات SQL المالية أو خريطة جداول الرفع.
- استبدال الطلب الحاجب بطلب OkHttp غير متزامن مربوط بإلغاء coroutine. يبقى رابط الإلغاء فعالًا أثناء قراءة جسم الرد، وليس أثناء انتظار الترويسات فقط. يُغلق جسم الرد قبل تسليم النتيجة، حتى عند تزامن الإلغاء مع الرد.
- إعادة المحاولة مرة واحدة لأخطاء الشبكة `IOException` فقط، مع حفظ سلسلة السبب. أخطاء API وJSON لا تُعاد، وأخطاء HTTP لا تُعتبر نجاحًا ولو تضمن الجسم `success=true`.
- تضييق التقاط الأخطاء في المسار الاحتياطي لفحص توكن D1 إلى `D1BackupException` كي لا يحوّل إلغاء coroutine إلى رسالة توكن غير صالح.
- التحقق من أن عنوان Worker هو جذر HTTPS بلا بيانات دخول أو مسار أو query أو fragment، وبمنفذ صالح. يُطبّع اسم النطاق بصورة مستقلة عن لغة الجهاز. الإدخال غير الصالح لا يكتب فوق العنوان المحفوظ.
- تضييق التقاط أخطاء تحليل التواريخ إلى `ParseException` مع بقاء أنماط التحليل وقواعد اليوم الفندقي دون تغيير.

حد مهم: إلغاء coroutine يوقف الطلب الحالي؛ زر `cancelUpload()` اليدوي ما زال يعمل بعقده السابق، أي فحص علامة الإلغاء بين الدفعات. لا ندّعي تحويل هذا الزر إلى إلغاء فوري لطلب HTTP.

## التنظيم دون تغيير العقود

- نقل `Screen` و`BackupUi` و`ReportDateRange` إلى ملفات بأسمائها، مع التحقق آليًا أن نص التصريحات المنقولة لم يتغير، وبقاء الحزم والأسماء العامة كما هي.
- إزالة اعتماد Context غير المستخدم من خدمة الإصلاح، واعتماد مستودع الحجوزات غير المستخدم من تقرير الديون، وتحليل تاريخ مغادرة مخطط لا تُستخدم نتيجته في الحسابات.
- استخدام `error` بدل الإنشاء المباشر لـ`IllegalStateException` في حارسي تعارض الحجز وحذف الغرفة، دون تغيير نوع الاستثناء أو رسالته أو شروط المنع.
- تصحيح نهايات ملفي حقن الاعتماد، وإزالة مؤهل مجلد أيقونة `v26` الزائد لأن minSdk يساوي 26.

أصبحت نتائج `UnusedPrivateProperty` و`MatchingDeclarationName` و`NewLineAtEndOfFile` و`UseRequire` و`UseCheckOrError` صفرًا في التحليل المقاس. لم تُعد ميزة عكس القيود أو إقفال الفترات الملغاة سابقًا.

## التحقق وحدوده

أضيف **11 اختبارًا**: سبعة لنقل D1 (من ضمنها سبع حالات رد غير صالح داخل اختبار واحد)، واثنان للتحقق من endpoint، واثنان لعقد نطاق اليوم الفندقي.

اختبارات D1 تستخدم `Call.Factory` مصطنعًا بالكامل: بلا DNS أو sockets أو توكنات حقيقية أو بيانات الفندق. تغطي نجاح الرد، حدود إعادة المحاولة، سلسلة السبب، إغلاق الجسم عند الفشل، الإلغاء أثناء الانتظار والقراءة، وسباق الرد مع الإلغاء.

- [اختبارات Android والبناء](https://github.com/NassarAlshabi1/marina-hotel-wit-app/actions/runs/37165042556): **نجاح كامل**: اختبارات الوحدة، APK الإصدار الموقّع وفحص توقيعات v1/v2/v3، Debug، والإصدار التشخيصي غير المصغّر.
- [التحليل والمحاكي](https://github.com/NassarAlshabi1/marina-hotel-wit-app/actions/runs/37165042566): المحاكي نجح؛ الجودة فشلت على Detekt المتبقي كما هو متوقع.
- تدقيق whitespace والتحقق من عدم تغيير نص التصريحات المنقولة نجحا محليًا.

لا يوجد اختبار كتابة على D1 الإنتاجي، أو قياس أداء جهاز حقيقي، أو اختبار UI مصادق لتدفق رفع/استعادة النسخ. نجاح المحاكي خاص بمسار الدخول/الإقلاع المعزول عن الشبكة.
