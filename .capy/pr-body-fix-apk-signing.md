Summary
- Fixes Flutter APK release build failures on GitHub Actions caused by Java 17 rejecting legacy keystore formats (e.g., "Tag number over 30 is not supported").
- Improves Base64 decoding in the workflow (printf + base64 -d) to avoid newline/compat issues.
- Requires regenerating a Java 17-compatible keystore and updating repo secrets.

Why
- GitHub Actions uses Java 17 (temurin). Older JKS/PKCS formats generated on legacy JDKs can fail to load under Java 17 due to stricter ASN.1 parsing and deprecated algorithms.
- The existing Base64 decode was generally fine, but using printf avoids potential newline artifacts.

What changed
- .github/workflows/flutter-apk-release.yml: replace echo | base64 --decode with printf "%s" | base64 -d for more robust decoding on Linux runners.
- No app code changes required.

Required actions (by repo maintainers)
1) Generate a new Java 17-compatible keystore (recommended: RSA-2048, JKS)
   Run locally:
   keytool -genkeypair -v \
     -keystore marina_hotel_release.jks \
     -alias marina-hotel-app \
     -keyalg RSA \
     -keysize 2048 \
     -validity 10000 \
     -keystore-type JKS \
     -storepass "Marina2025SecureKey" \
     -keypass "Marina2025SecureKey" \
     -dname "CN=Marina Hotel App, OU=IT, O=Marina Hotel, L=Riyadh, ST=Riyadh, C=SA"

2) Encode the keystore to Base64 as a single line
   base64 -i marina_hotel_release.jks | tr -d '\n'

3) Update GitHub Actions Secrets (Settings → Secrets and variables → Actions)
   - KEYSTORE_BASE64: <paste the new single-line Base64>
   - KEYSTORE_PASSWORD: Marina2025SecureKey
   - KEY_ALIAS: marina-hotel-app
   - KEY_PASSWORD: Marina2025SecureKey

4) Trigger the workflow (Actions → Build Flutter Release APK → Run workflow) and verify
   - Configure Android Signing Files step completes
   - Build release APK step succeeds (no KeytoolException)
   - Signed APK artifact is uploaded

Alternative (preserve original identity)
If you must keep the existing signing identity, try converting the old keystore on a modern JDK and re-uploading:

keytool -importkeystore \
  -srckeystore <old>.jks \
  -destkeystore marina_hotel_updated.jks \
  -deststoretype JKS \
  -srcstoretype JKS

Notes
- The root cause is the keystore format/encoding; CI decoding was working. The workflow change just makes decoding more robust. The essential fix is supplying a keystore generated with a modern JDK (17+ compatible).
- Gradle already reads android/key.properties and uses android/app/release.keystore for signing in release builds.
