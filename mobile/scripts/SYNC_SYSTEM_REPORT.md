## 🔄 سيناريوهات المزامنة

### السيناريو 1: مزامنة عادية (كل 15 دقيقة)

```
1. فحص الاتصال
2. قفل المزامنة (SyncMutex)
3. فحص قاطع الدائرة (CircuitBreaker)
4. Push: رفع التغييرات من Outbox
5. Pull: سحب التغييرات الجديدة
6. حل التضاربات
7. تحديث الطابع الزمني
8. فتح القفل
```

### السيناريو 2: الجهاز الجديد (أول مزامنة)

```
1. Full Pull من جميع الجداول
2. بناء المرآة المحلية (Mirror)
3. تحديث localId ↔ serverId mappings
4. تسجيل الجهاز في Appwrite
```

### السيناريو 3: استعادة بعد انقطاع

```
1. فحص آخر timestamp
2. Delta Sync من lastPullTs
3. حل التضاربات
4. تصحيح الـ FKs
5. إعادة حساب الحقول المشتقة
```

## ⚠️ المخاطر المحتملة

### 1. فقدان البيانات

| المخاطر | الاحتمالية | التأثير | الحل |
|---------|------------|--------|------|
| فشل Push | متوسطة | عالي | Outbox يبقى محلياً حتى نجاح Push |
| فشل Pull | منخفضة | متوسط | إعادة المحاولة التلقائية |
| تضارب دون حل | منخفضة | عالي | newerWins strategy |
| حذف غير مقصود | منخفضة | عالي | soft delete + audit log |

### 2. مشاكل الشبكة

| المخاطر | الحل الحالي |
|---------|-----------|
| انقطاع الشبكة | Adaptive batch + retry |
| بطء الشبكة | Delta sync + compression |
| Timeout | 3 retries with exponential backoff |

### 3. مشاكل التكامل

| المخاطر | الحل الحالي |
|---------|-----------|
| يتيم Foreign Key | ID resolver مع 3 طرق بحث |
| عدم مزامنة الحقول المشتقة | recalculateBookingById() |

## 💡 التوصيات

### ✅ ما يعمل جيداً

1. **Outbox Pattern**: يضمن عدم فقدان البيانات حتى لو فشلت المزامنة
2. **Idempotency Keys**: تمنع الإرسال المكرر
3. **Delta Sync**: فعال للشبكات البطيئة
4. **Adaptive Batch**: يتكيف مع أداء الشبكة
5. **Circuit Breaker**: يمنع الحمل الزائد
6. **Foreign Key Resolution**: ذكي مع 3 طرق بحث
