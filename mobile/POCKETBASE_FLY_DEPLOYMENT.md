# دليل نشر PocketBase على Fly.io وربطه بتطبيق الموبايل

هذا الدليل يشرح خطوة بخطوة كيفية تشغيل خادم PocketBase على منصة Fly.io وربطه بتطبيق الموبايل (Flutter) حتى تعمل المزامنة ثنائية الاتجاه بين الأجهزة.

---

## 1. نظرة عامة
- **PocketBase** سيكون خادم المزامنة المركزي.
- **Fly.io** توفّر استضافة مجانية صغيرة مناسبة للتشغيل الدائم (256MB RAM + 1GB Volume).
- بعد النشر، ستستخدم أجهزة أندرويد الحسابات التي تُنشئها في PocketBase للمزامنة الفورية.

---

## 2. المتطلبات المسبقة
1. حساب Fly.io (يمكن التسجيل مجاناً): https://fly.io/dashboard
2. صلاحية الوصول إلى مشروعك محلياً أو على سطر الأوامر (المجلد الذي يحتوي `server/`).
3. التوكن الشخصي من Fly.io (Access Token) – سنتطرّق لطريقة توليده لاحقاً.

---

## 3. تثبيت أداة **flyctl**
على أي جهاز (Windows / macOS / Linux):
```bash
curl -L https://fly.io/install.sh | sh
```
> ملاحظة: في Windows يمكن استخدام PowerShell أو تنزيل الأداة من https://fly.io/docs/hands-on/install-flyctl/.

بعد التثبيت، تأكد أن المسار أُضيف لمتغيرات البيئة، ثم نفّذ:
```bash
flyctl version
```
إذا ظهر رقم الإصدار، فالأداة جاهزة.

---

## 4. توليد Access Token من Fly.io
1. افتح https://fly.io/dashboard
2. من القائمة الجانبية اختر **Access Tokens**.
3. اضغط **Create new token**.
4. أعطِ التوكن اسماً (مثلاً `pocketbase`)، ثم اضغط إنشاء.
5. انسخ التوكن بالكامل (يبدأ بـ `FlyV1 ...`) واحتفظ به في مكان آمن.

> التوكن لن يظهر مرة أخرى، لذلك تأكد من نسخه كاملاً فوراً.

### استخدام التوكن مع `flyctl`
في الطرفية:
```bash
export FLY_ACCESS_TOKEN="FlyV1 ...."
flyctl auth whoami
```
- إذا نجح الأمر سيظهر بريدك الإلكتروني على Fly.
- إذا ظهر خطأ 401، فربما التوكن منتهي أو نُسخ بشكل غير كامل.

> على Windows استخدم `setx FLY_ACCESS_TOKEN "FlyV1 ..."` في PowerShell، ثم افتح نافذة جديدة.

---

## 5. الدخول إلى مجلد الخادم
من مجلد المشروع:
```bash
cd server
```
هنا توجد ملفات: `Dockerfile`, `fly.toml`, `pb_schema.json`.

---

## 6. إنشاء تطبيق Fly لأول مرة (مرة واحدة فقط)
```bash
flyctl launch --no-deploy
```
خلال التنفيذ:
- سيعرض اسم التطبيق (يمكن قبول الاسم المقترح أو كتابة اسم جديد، مثلاً `marina-hotel-pocketbase`).
- سيطلب تحديد المنطقة، اختر الأقرب (مثل `ams` أو `cdg`).
- عندما يسألك عن إنشاء volume، اختر **No** الآن (سننشئه في الخطوة التالية يدوياً).

> الأمر يولّد ملف `fly.toml` (موجود مسبقاً في المشروع، لذلك قم بتأكيد استخدامه عند السؤال).

---

## 7. إنشاء وحدة تخزين دائمة (Volume)
الهدف حفظ بيانات PocketBase بين عمليات إعادة التشغيل.
```bash
flyctl volumes create pb_data --size 1
```
- الحجم 1GB يكفي لمعظم الاستخدامات الصغيرة.
- استخدم نفس المنطقة التي اخترتها في خطوة launch.

إذا ظهرت رسالة أن المجلد موجود مسبقاً، تجاهل الخطوة (المقصود أنه تم إنشاؤه سابقاً).

---

## 8. النشر الفعلي
```bash
flyctl deploy
```
سيقوم الأمر بـ:
- بناء صورة Docker (تستخدم `Dockerfile` الموجود).
- رفعها إلى Fly.
- تشغيل التطبيق على منفذ 8080 (بحسب `fly.toml`).

أثناء النشر، تأكد من:
- لا توجد أخطاء في التحزيم.
- تم ربط volume بنجاح (`pb_data`).

إذا احتجت إعادة النشر لاحقاً (بعد تغييرات على PocketBase)، يكفي تشغيل `flyctl deploy` من نفس المجلد.

---

## 9. الحصول على رابط التطبيق
بعد النشر:
```bash
flyctl info
```
ابحث عن الحقل `Hostname` (مثال: `https://marina-hotel-pocketbase.fly.dev`).

> هذا هو رابط الـ API ولوحة التحكم أيضًا.

---

## 10. إعداد PocketBase بعد النشر
1. افتح الرابط في المتصفح ثم أضف `/_/` في النهاية:
   ```
   https://marina-hotel-pocketbase.fly.dev/_/
   ```
2. أنشئ مستخدم **Admin** جديد (البريد وكلمة المرور من اختيارك).
3. من لوحة التحكم → Collections → استيراد (Import) واختَر الملف `pb_schema.json` الموجود في مجلد `server/` داخل المشروع.
4. بعد الاستيراد ستظهر المجموعات الـ 7 (rooms, bookings, ...).
5. من تبويب Users أنشئ مستخدمي التطبيق:
   - فندق: `hotel@marinahotel.local` (مثلاً)
   - منزل: `home@marinahotel.local`

> هذه الحسابات هي ما سيستخدمه تطبيق الموبايل لتسجيل الدخول والمزامنة.

---

## 11. تحديث إعدادات تطبيق الموبايل
داخل `mobile/lib/utils/env.dart` يوجد:
```dart
static String pocketbaseUrl = const String.fromEnvironment(
  'POCKETBASE_URL',
  defaultValue: 'https://marina-hotel-pocketbase.fly.dev',
);
```
- إذا كان الرابط مختلفاً استخدم الأمر التالي عند تشغيل التطبيق أو البناء:
  ```bash
  flutter run --dart-define=POCKETBASE_URL=https://YOUR-APP.fly.dev
  ```
- أو عدّل القيمة الافتراضية في الملف ليطابق رابط Fly.

بعدها احرص على تنفيذ:
```bash
cd mobile
flutter pub get
```

---

## 12. اختبار المزامنة على الهاتفين
1. ثبّت التطبيق على الجهاز الأول وسجّل الدخول بالبريد `hotel@...`.
2. ثبّت التطبيق على الجهاز الثاني وسجّل الدخول بـ `home@...`.
3. أنشئ سجلاً (مثلاً غرفة جديدة) على الجهاز الأول.
4. خلال ثوانٍ يجب أن تظهر على الجهاز الثاني (بفضل Realtime).
5. جرّب الوضع غير المتصل (Offline) ثم أعد الاتصال للتأكد أن Outbox يدفع التغييرات وتُسحب من الخادم.

---

## 13. نشر تحديثات لاحقة لـ PocketBase
كلما عدّلتَ ملفات الخادم (مثلاً: `pb_schema.json` أو `Dockerfile`):
```bash
cd server
flyctl deploy
```
- سيعيد بناء الصورة ونشر الإصدار المُحدّث.
- البيانات تبقى محفوظة في volume `pb_data`.

### مراقبة السجلات
```bash
flyctl logs
```
لمراقبة الأخطاء أو رسائل PocketBase.

---

## 14. صيانة التوكنات
- التوكن (Access Token) قد تنتهي صلاحيته، عند حدوث ذلك كرر الخطوة 4 لتوليد توكن جديد.
- يمكن وضع التوكن في ملف `~/.fly/config.yml` أو متغير بيئي دائم.
- لا تشارك التوكنات على العلن.

---

## 15. استكشاف الأخطاء
| المشكلة | السبب المحتمل | الحل |
|---------|---------------|------|
| `You must be authenticated to view this.` عند `flyctl auth whoami` | التوكن غير صحيح أو ناقص | تأكد من نسخ التوكن كاملاً وإعادة التصدير |
| `volume already exists` | سبق إنشاء الـ Volume | يمكن تجاهل الرسالة أو حذف الـ Volume القديم إذا رغبت |
| التطبيق لا يستجيب | التطبيق لم يُنشر أو حدث فشل في البناء | راجع `flyctl status` و `flyctl logs` |
| Realtime لا يعمل | PocketBase أو الرابط غير صحيح | تأكد من URL في `Env.pocketbaseUrl`، وتحقق من قوانين الـ Collections |
